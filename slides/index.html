03

Streaming de HTML y JSON

Muestra valor desde el primer token sin bloquear el hilo principal.

// Streaming de JSON

Parsea cada carácter una sola vez

JSON.parse(buffer) en cada tokenO(n²)5 KB → ~6,5 M caracteres recorridos
Parser incrementalO(n)5 KB → 5 KB recorridos

Emite eventos (field, item) y renderiza por ítem completo, no por carácter.

stream.ts~120 líneas sin dependencias
const parser = new IncrementalJSON();
for await (const chunk of stream) {
  for (const ev of parser.push(chunk)) {
    if (ev.type === 'item')
      store.upsert(ev.path, ev.value);
  }
}
// ✗ lo que NO hacer:
// buffer += chunk; ui = repair(JSON.parse(buffer))

// 70 tokens/s ≠ 70 renders/s

Un render por frame y cede el hilo

scheduler.tsrAF + scheduler.yield()
let dirty = false;
function onToken(ev) {
  store.apply(ev);
  if (!dirty) { dirty = true; requestAnimationFrame(flush); }
}
async function flush() {
  dirty = false;
  for (const part of store.takeChanges()) {
    render(part);
    await scheduler.yield();  // deja pasar clics
  }
}

new PerformanceObserver((list) => {

    for (const s of f.scripts)
      console.log(s.sourceFunctionName,
                  s.duration);
}).observe({ type: 'long-animation-frame',
             buffered: true });

Recicla, virtualiza, contén

Pool de nodos

Solo existen los nodos visibles. Los que salen por arriba se reutilizan para los que entran por abajo: el DOM no crece aunque la lista sí.

content-visibility

Secciones generadas que ya terminaron y están fuera de pantalla no se pintan, con contain-intrinsic-size para no saltar.

Mide la memoria

Una UI generativa vive horas abierta. DevTools for agents ya analiza heap snapshots y nodos desconectados.

Regla: el tamaño del DOM depende de la pantalla, no de la respuesta del modelo.
